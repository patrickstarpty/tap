# TAP 产品原型基准规范

创建日期：2026-09-22。

本文规定产品设计的唯一持续演进基准、模块保留规则和回归要求。规则发现入口为根 [AGENTS.md](../../AGENTS.md)，启动入口同步在 [README](../../README.md#最新产品原型以-main-为准)。本文不改变已接受的架构 ADR，也不代表后端能力已完成。

## 唯一基准与固定入口

`main` 主分支始终承载最新已确认的完整原型。原型变更确认后，源码、资源、回归检查和 README 入口说明须一并合入 `main`，不能仅保留在功能分支、worktree 或临时目录；历史截图不作为最新版本的发现入口。

完整组合原型恢复为唯一设计基准，沿用已有产品壳、视觉体系、模块和交互；后续需求在同一原型上增量修改。主入口为 [TapProductPrototype.tsx](../../apps/web/src/widgets/tap/TapProductPrototype.tsx)，复用 `apps/web/src/legacy/` 内已有测试资产与自动化实现。不得为每个新需求重新创建独立原型、另起产品壳或使用 `?prototype=review` 等另一套评审入口替代它。

从仓库根目录运行：

```sh
corepack pnpm --dir apps/web dev --port 15176
```

固定浏览地址为 `http://127.0.0.1:15176/prototype`。TAP AI 与 TAP 的独立应用入口继续服务各自实现和部署，不能替代此完整产品体验基准。

## 必须保留的模块与旅程

| 模块或能力 | 可验证的基准要求 |
| --- | --- |
| 产品壳与导航 | 保留统一品牌、一级模块导航、Tapper 二级导航及折叠行为；从各模块可返回 Tapper。 |
| Tapper | `New chat`、会话历史、Composer、Knowledge/Agent/Skill 上下文、模型选择与知识来源面板可访问；返回会话保留当前会话与草稿。 |
| Agents 与 Skills | 保留各自目录、详情或创建入口，以及在 Tapper 中使用的旅程。 |
| Library 与 Knowledge Graph | 保留文档目录与筛选、来源入口、图谱搜索定位、节点关系与来源跳转、缩放和全屏探索。 |
| Test Management | 保留测试资产列表、Test Plan 详情、Scenario/BDD 步骤、Test Data、Automation 关联与运行记录入口。 |
| Test Analytics / Insights | 保留一级分析入口和已有分析视图；新增 Insights 能力在此延展，不能删除其他模块来突出分析。 |
| Low Code Automation | 保留列表、创建、详情、BDD 与动作映射、动作编辑、AI 辅助、运行与历史入口。 |
| 跨模块关联 | 保留 Tapper 生成并打开测试资产、Test Plan 与 Automation 双向跳转、可选严格 `1:1` 关联及关联资产共享 Run 的交互语义。 |
| Tapper 悬浮助手 | 保留 Test Management 与 Low Code Automation 的助手入口、当前页面上下文、快捷提问、未读状态，以及携会话和草稿在 Tapper 中继续。 |

近期交付聚焦知识问答和基础 Insights，只缩窄实施与验收范围，不允许因此移除、隐藏为不可达或以空白占位替换其他已设计模块。调整既有模块的结构或能力须有明确产品需求；新增需求本身不构成删除原设计的授权。

## 产品界面与实现边界

原型应呈现拟交付产品的用户界面。页面、菜单、对话、结果与错误状态采用用户能理解的产品语言，不包含演示开关、模拟场景选择器、测试控制面板、模拟运行标签或实现说明。确定性示例数据、故障注入与场景切换放在页面外的测试工具中，能力边界放在文档与评审记录中。正常的用户操作与业务状态仍应完整保留。

原型能展示某项交互，不代表模型、服务端持久化、Pipeline、浏览器或移动设备已经接通，不构成真实执行证据。TAP AI 与 TAP 的代码、运行时和部署边界仍遵循[产品边界规范](../architecture/2026-09-15-tap-ai-product-boundary.md)及已接受 ADR；本规范只统一产品体验设计，不合并应用实现。

## 截图与交互回归

[客户原型演示指南](2026-09-04-customer-prototype-demo-guide.md)及 `docs/assets/prototype-demo/` 的 44 张图片是 2026-09-06 的历史采集，仍用于追溯已认可的视觉、布局与旅程。截图的历史属性不表示完整原型已废弃；其中的演示标签、模拟场景和旧 Provider 文案也不作为当前产品 UI 的要求。历史截图未覆盖的模块仍须按上表保留。

每次改变产品 UI 时，在同一 `/prototype` 入口、相同视口与确定性数据条件下采集变更前后截图并人工对照，至少覆盖受影响页面及共享壳；截图使用 1280×720 布局视口、2× 像素密度（2560×1440 PNG），新增响应式需求另补对应视口。回归记录应标明变更目的、前后截图和检查结果，历史截图不得被无说明地覆盖。

验收须逐项确认上表模块仍可导航到达、受影响旅程可操作，并检查 Tapper → Test Plan → Automation 的关联跳转和悬浮助手 → Tapper 的会话交接。只验证新增页面或只提供局部截图不足以证明完整基准没有退化。真实服务能力另按相应测试与验收规范验证。
