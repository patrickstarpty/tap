# V1 总纲

V1 收敛为 TAP AI 内的 6 项能力，全局版本顺序见[产品路线图](2026-10-01-product-roadmap.md)。本文件只做索引与验收，实施步骤见各子项目的 spec 与 plan。范围来源：[架构与实施评审及 V1 范围收敛](../../archive/reviews/2026-09-29-architecture-review-and-v1-scope.md)；现状见[现状架构](../../architecture.md)。

## 状态约定

每项能力用两个勾选框：

- **工程完成**：代码与自动化测试可证明。
- **业务验证**：需真实资料或用户，单独勾选，不阻塞工程完成。

### 4. Skills/Agents

- [x] 工程完成：导入 `SKILL.md`/包（含 `scripts/`、`references/`）或界面新建均生成不可变 Revision（迁移 `0035_skills_agents_authoring`）；Agent = 系统提示词 + Skills + 工具白名单 + 默认模型；工具白名单由代码定义的工具注册表（`modules/ai/domain/tools.py`，PR 5 起四项内置，`graph.relations`、`insights.query` 可勾选）替代四处硬编码；Skill 指令经 `modules/knowledge/adapters/litellm.py` 的提示词组装真实进入回答，Turn 冻结 Skill 选择，重试/回放复用冻结修订；`GET /ai/agents/{revisionId}`、`GET /ai/skills/{revisionId}` 返回修订详情；Skill 包存对象存储独立命名空间（`skills/{skill_id}/{revision_id}/<相对路径的 sha256>`），包内代码（`scripts/`、`assets/`）只存档永不执行，frontmatter `allowed-tools` 原样展示但不授予任何工具权限；MCP server 登记与 MCP 工具不在 V1（2026-10-11 决定略过，见 [ADR-032](../../decisions/2026-10-12-adr-032-skill-packages-and-tool-registry.md)）
- [ ] 业务验证：导入至少一个真实外部 Skill 并在对话中使用

### 5. 可观测性

- [x] 工程完成：OpenTelemetry 埋点写入 MySQL，可选 OTLP 导出到任意后端；每个 Turn 有 trace ID，trace 含检索、图谱扩展、模型调用、工具调用 span 及 token 与成本；token 用量持久化到 MySQL；前端从回答跳转调用链并显示 token 面板；每次模型调用持久化模型名、实际上游模型、供应商与 token 用量，历史回答可查看当时的实际模型
- [x] 工程完成：Langfuse 运营看板与用户反馈——同步 worker 把 MySQL 链路数据与回答反馈脱敏后镜像到本地 Langfuse（compose profile `langfuse`），支持按会话/用户/项目/模型筛选成本、延迟、用量、满意度；回答可点赞/点踩并附可选评论，落 MySQL 并同步为 Langfuse score；Langfuse 不可用期间的数据恢复后全部补齐（[设计](../specs/2026-10-14-langfuse-ops-observability-design.md)）
- [ ] 业务验证：用真实对话排查一次问题
  - 2026-10-15 可观测性替代验收：暂无真实项目用户，在本地 demo（8 份公开产品条款、`qwen-plus` 真实模型、验收时自拟的对话）上，借助调用链与 Langfuse 定位并修复两个真实问题：① Langfuse 成本比 MySQL `model_call` 少约 36%，追到推荐问题刷新未绑定 trace 范围、其 span 被导出器丢弃（f49688f）；② 推荐问题刷新持续失败，按 `model_call` 失败记录追到上下文含未脱敏的近期提问被网关拒绝（db5d9f6）。仍需在真实项目中由用户反馈的问题复验。
