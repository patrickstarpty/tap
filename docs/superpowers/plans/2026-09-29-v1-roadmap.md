# V1 总纲

V1 收敛为 TAP AI 内的 5 项能力，全局版本顺序见[产品路线图](2026-10-01-product-roadmap.md)。本文件只做索引与验收，实施步骤见各子项目的 spec 与 plan。范围来源：[架构与实施评审及 V1 范围收敛](../../archive/reviews/2026-09-29-architecture-review-and-v1-scope.md)；现状见[现状架构](../../architecture.md)。

## 状态约定

每项能力用两个勾选框：

- **工程完成**：代码与自动化测试可证明。
- **业务验证**：需真实资料或用户，单独勾选，不阻塞工程完成。

## 能力与验收

### 1. 可靠问答

- [x] 工程完成：仓库内 golden set 格式与回归命令，CI 用 fake 模型运行、真实模型可选；LiteLLM 流式输出，SSE 由 worker 事件驱动逐 token 下发，替换 100ms 轮询；租约回收递增 `attempt` 且有上限，瞬时失败退避重试，worker loop 单次异常不退出；持久化集成测试缺 MySQL 时明确报告而非静默跳过；新对话页推荐问题按知识库与使用情况生成、经依据校验，不显示失效或过期推荐（[推荐问题设计](../specs/2026-09-30-tapper-prompt-suggestions-design.md)）
- [ ] 业务验证：30–50 条真实标注问答跑出基线分数并记录；真实项目中显示的推荐问题点击发送后至少 90% 得到有依据的回答
  - 2026-10-05 推荐问题替代验收：暂无真实项目文档，以友邦人寿官网公开的 8 份产品条款（重疾、豁免、年金、团体医疗、终身寿险、护理）为知识库，`qwen-plus` 真实模型，3 轮重新生成共显示 17 条推荐（中英文），逐条发送后 16 条得到带引用的回答（94%，单轮 75%–100%）；仍需在真实项目中复验。

### 2. 知识图谱展示

- [x] 工程完成：查询不再每次整快照载入内存，按快照缓存邻接表；本地基准约 1 万节点、5 万边下查询 p95 < 300ms；按项目已发布知识生成“领域总览”视图（覆盖项目全部已就绪来源，安全上限 2000 个，超出时响应与界面标记截断；TAP AI 前端在此之前只提供“已发布来源图谱”，见 [TAP AI 前端清理原型内容](2026-09-30-tap-ai-frontend-demo-cleanup.md)）
  - 2026-11-04 `make graph-bench`（1 万节点、5 万边，缓存预热后各 200 次）：搜索 p95 1.01ms、邻居（深度 2）p95 4.88ms、路径 p95 0.30ms；基准夹具绕过单快照发布上限（500 节点 / 2000 边），只衡量索引查询。
- [ ] 业务验证：真实资料生成的图谱可浏览

### 3. 图谱脉络分析

- [x] 工程完成：检索片段 → 实体 → 1–2 跳扩展 → 有界 LangGraph 工具循环（步数上限）→ 回答同时引用关系边与原文片段；点击引用在图谱中高亮路径；golden set 含关系类问题子集
- [ ] 业务验证：真实关系类问题人工评审

### 4. Skills/Agents

- [x] 工程完成：导入 `SKILL.md` 生成不可变 Revision；Agent = 系统提示词 + Skills + 工具白名单 + 模型；工具注册表替代硬编码白名单；可注册 MCP server，其工具可加入白名单；导入 Skill 不执行内含代码
- [ ] 业务验证：导入至少一个真实外部 Skill 并在对话中使用

### 5. 可观测性

- [x] 工程完成：OpenTelemetry 埋点写入 MySQL，可选 OTLP 导出到 Phoenix（compose profile `observability`）；每个 Turn 有 trace ID，trace 含检索、图谱扩展、模型调用、工具调用 span 及 token 与成本；token 用量持久化到 MySQL；前端从回答跳转调用链并显示 token 面板；每次模型调用持久化模型名、实际上游模型、供应商与 token 用量，历史回答可查看当时的实际模型
- [ ] 业务验证：用真实对话排查一次问题
