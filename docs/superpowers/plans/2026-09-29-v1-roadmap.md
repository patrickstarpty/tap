# V1 总纲

V1 收敛为 TAP AI 内的 6 项能力，全局版本顺序见[产品路线图](2026-10-01-product-roadmap.md)。本文件只做索引与验收，实施步骤见各子项目的 spec 与 plan。范围来源：[架构与实施评审及 V1 范围收敛](../../archive/reviews/2026-09-29-architecture-review-and-v1-scope.md)；现状见[现状架构](../../architecture.md)。

## 状态约定

每项能力用两个勾选框：

- **工程完成**：代码与自动化测试可证明。
- **业务验证**：需真实资料或用户，单独勾选，不阻塞工程完成。

## 能力与验收

### 1. 可靠问答

- [ ] 工程完成：仓库内 golden set 格式与回归命令，CI 用 fake 模型运行、真实模型可选；持久化集成测试缺 MySQL 时明确报告而非静默跳过；新对话页推荐问题按知识库与使用情况生成、经依据校验，不显示失效或过期推荐（[推荐问题设计](../specs/2026-09-30-tapper-prompt-suggestions-design.md)）；对话链路的流式下发与租约重试并入能力 6 子项目 ②
- [ ] 业务验证：30–50 条真实标注问答跑出基线分数并记录；真实项目中显示的推荐问题点击发送后至少 90% 得到有依据的回答
  - 2026-10-05 推荐问题替代验收：暂无真实项目文档，以友邦人寿官网公开的 8 份产品条款（重疾、豁免、年金、团体医疗、终身寿险、护理）为知识库，`qwen-plus` 真实模型，3 轮重新生成共显示 17 条推荐（中英文），逐条发送后 16 条得到带引用的回答（94%，单轮 75%–100%）；仍需在真实项目中复验。

### 2. 知识图谱展示

- [ ] 工程完成：查询不再每次整快照载入内存，按快照缓存邻接表；本地基准约 1 万节点、5 万边下查询 p95 < 300ms（`make graph-bench`，opt-in）；按项目已发布知识生成“领域总览”视图（TAP AI 前端在此之前只提供“已发布来源图谱”，见 [TAP AI 前端清理原型内容](2026-09-30-tap-ai-frontend-demo-cleanup.md)）
- [ ] 业务验证：真实资料生成的图谱可浏览

### 3. 图谱脉络分析

- [ ] 工程完成：关系分析 Agent 子图：检索种子 → 多跳扩展 → 路径推理 → 边引用；初版不经 LangGraph 工具循环，能力 6 落地后关系分析迁为 agent 循环中的 `graph.relations` 工具
  - [x] 回答同时引用关系边与原文片段
  - [x] 点击引用在图谱中高亮路径（已合并到 develop 并通过验收）
  - [ ] golden set 含关系类问题子集；CI 常驻门禁 `make quality-graph-relations`（假抽取 + 确定性模型，只验证链路接线/引用形状/评测脚本本身，不代表真实关系抽取准确率）；真实门禁 `make quality-graph-relations-real`（opt-in，人工标注，题目须含若干 `expectedSources` 跨 2+ 份文档）；门禁工具已合并到 develop；真实 golden set 待人工标注（Task 8）
- [ ] 业务验证：真实关系类问题人工评审

已知局限（详见[现状架构](../../architecture.md)已知差距表）：合并节点的 label/别名取全部片段成员中的多数值，可能反映未发布或未经审阅来源的措辞；种子选取与关系排序是确定性启发式而非通用推理，规划器的关系意图判定本身也是启发式，复杂问题走模型规划器；当前运行时 `publication_authority` 为 `None`，关系证据的发布授权复检不执行，R 证据片段（≤300 字）不过流程图发布闸门，可能引用未经审阅的流程图切片内容。

### 4. Skills/Agents

- [ ] 工程完成：导入 `SKILL.md` 生成不可变 Revision；Agent = 系统提示词 + Skills + 工具白名单 + 模型；工具注册表替代硬编码白名单；可注册 MCP server，其工具可加入白名单；导入 Skill 不执行内含代码
- [ ] 业务验证：导入至少一个真实外部 Skill 并在对话中使用

### 5. 可观测性

- [x] 工程完成：OpenTelemetry 埋点写入 MySQL，可选 OTLP 导出到 Phoenix（compose profile `observability`）；每个 Turn 有 trace ID，trace 含检索、图谱扩展、模型调用、工具调用 span 及 token 与成本；token 用量持久化到 MySQL；前端从回答跳转调用链并显示 token 面板；每次模型调用持久化模型名、实际上游模型、供应商与 token 用量，历史回答可查看当时的实际模型
- [ ] 业务验证：用真实对话排查一次问题

### 6. LangGraph 编排

设计见 [Tapper LangGraph 编排设计](../specs/2026-10-14-tapper-langgraph-orchestration-design.md)（一份 spec、7 个 PR），目标架构见 [ADR-029](../../decisions/2026-09-18-adr-029-langgraph-ai-interaction-task-orchestrator.md)。能力 4 先完成，其 Agent 与工具注册表作为本能力的输入。

- [ ] ② 图重构：对话回答与 Insights 解释迁入版本化图 `tapper-chat-v2`，按节点 checkpoint 续跑（测试设计生成保留旧图）；LiteLLM 流式输出，正文内联引用，SSE 经 Redis 逐 token 下发，替换 100ms 轮询；可立即停止生成；租约回收递增 `attempt` 且有上限，瞬时失败退避重试，worker loop 单次异常不退出
- [ ] ③ 角色定义与意图识别：Tapper 基础角色版本化且不可被 Agent 覆盖；Agent 角色与工具白名单在图内生效；planner 输出意图用于观测、评测与范围外拒答
- [ ] ④ 围栏：步骤/时间/调用/费用预算在图内统一执行；提示注入隔离与检测、工具参数范围校验；输入输出敏感信息脱敏；范围外拒答；预算耗尽时明确停止并说明原因
- [ ] ⑤ 工具调用与长任务编排：单一受限 ReAct 循环经工具注册表调用工具（多步检索、关系分析、Insights 联合分析）；整份文档分析长上下文优先、超出走可恢复的 map-reduce 长任务；高成本动作经用户确认后继续；步骤与进度可见
- [ ] ⑥ 可信知识（有据可依、不胡编）：所有对话回答经统一引用校验与模型依据支撑校验，不支撑的内容删除或整体弃答；关系证据发布授权复检生效；诱导胡编子集门禁通过
- [ ] 业务验证：真实项目中用一个自定义 Agent 完成一次多步工具任务并人工评审
