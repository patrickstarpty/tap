# Tapper 实时浏览器 Agent 与动作脚本回放

日期：2026-11-08。用户已确认职责分工：browser-use 完成网页任务，OpenCode 将成功操作整理成可维护脚本，TAP 管理会话、控制和证据。浏览器采用 TAP 管理的独立实例，支持查看过程、登录和人工接管；默认生成脚本供用户回放。本文细化该方向，尚不代表能力已实现或接入已验证。跨模块决定见 [ADR-038](../../decisions/2026-11-08-adr-038-browser-agent-and-script-ownership.md)。

## 当前实现修正

2026-11-08 后续用户已确认 [BDD 合约执行器](2026-11-08-tapper-bdd-executor-design.md)。其冻结步骤、输入与断言、TAP 持有执行顺序、常见动作确定性生成脚本的规定，取代下文关于执行中由 Agent 调整计划及默认 OpenCode 整理的相应条款。其他未交付能力仍不转记为已完成，详见 ADR-038。

## 1. 产品行为与边界

用户提供目标、起始网址和必要资料。Tapper 在同一浏览器任务中观察页面、选择动作、执行并核对结果；可处理查询、筛选提取、填表、多页和多标签导航、文件上传下载。用户能查看正在操作的页面、接管登录或处理障碍，再交还 Agent 继续。用户无需编写脚本、定位器或测试计划。

沿用现有自然语言自动路由和业务步骤进度：用户不必选择 browser-use 或 OpenCode。已保存的 BDD 业务步骤继续作为进度与动作关联依据；由当前 browser-use 执行阶段提出或调整步骤，TAP 保存修订后接收关联动作，不额外引入第二个浏览器规划 Agent。现有 Outputs/Subagents/Sources 展示结构继续使用，在运行详情内补充浏览器画面和控制。

每次成功任务默认进入脚本整理阶段，输出 Playwright + TypeScript 脚本、输入参数说明、人工前置条件及动作来源映射。首次业务执行和脚本整理分别报告结果：业务已完成但脚本整理失败时，显示“任务已完成，回放脚本生成失败”，只允许重试整理，不重新执行已完成的业务。

“查看过程”展示已发生的动作与证据，不访问目标网站。“执行回放”由用户主动发起，会再次操作网站并产生新的任务和执行记录；提交、发送等业务动作也可能再次发生。生成脚本不触发回放，不为验证代码自动重复业务操作。回放入口展示目标、输入、登录前置条件和会产生外部变化的步骤；用户按任务范围授权执行，不要求每次普通点击都确认。

首版设计默认值：同一任务暂停、补料和接管期间保留存活浏览器的登录状态；每个新任务使用独立浏览器，不自动复制其他任务的账号状态。跨任务账号档案另行设计。页面刷新只恢复 TAP 运行视图，不重启任务。浏览器进程丢失后不承诺原位恢复，不通过重放已提交动作恢复登录。

本轮仍限于本机回环 Demo 和现有项目作用域。支持独立受控浏览器，不接管用户日常 Chrome，不引入 Browser Use Cloud 托管依赖，不扩展 LAN/生产部署或完整测试资产发布范围。

## 2. 方案与取舍

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| browser-use 在线执行，OpenCode 整理脚本 | 浏览器任务循环与代码整理各有明确负责人；符合用户已确认方向 | 新增 browser-use 适配、动作采集和控制交接；采用此方案 |
| OpenCode 直接操作浏览器并产出脚本 | 延续现有模型运行通路 | 浏览器策略、视觉观察与恢复能力需要继续建设；保留旧模式兼容，不作为新主路径 |
| browser-use 历史直接作为最终回放资产 | 可使用原生历史重放和变量替换 | 仍依赖 browser-use，部分步骤调用模型，不能代替独立 Playwright 脚本；仅作适配参考 |

选择依据是职责与产品目标匹配，不宣称 browser-use 在本项目的成功率或成本已优于 OpenCode。固定依赖版本、实际模型兼容、接管与动作采集均需通过第 10 节门禁。

## 3. 模块所有权与执行通路

| 组件 | 职责 | 权限边界 |
| --- | --- | --- |
| TAP AI workflow 应用层 | 任务准入、阶段推进、用户输入、累计预算、模型调用归属、运行视图投影 | 推进阶段，不与 browser-use 并行规划浏览器动作 |
| browser-use adapter/runtime | 在冻结目标与授权范围内观察、决策、执行、反馈；提交结果候选与动作轨迹 | 在线阶段唯一 AI 浏览器操作者；使用开源 Python 库与现有 LiteLLM 通路 |
| TAP 非 AI `browser_automation` | 浏览器实例、控制权租约、动作回执、结果证据、脚本包、回放执行与资源终止 | 浏览器执行权威；无模型密钥，不承担模型规划 |
| OpenCode script runtime | 读取冻结轨迹和页面证据，生成或修复脚本、参数说明和来源映射 | 无在线浏览器控制凭据；不重复业务操作；模型仍经 LiteLLM |
| Tapper 前端 | 任务结果、实时画面、接管/交还、补料、动作时间线、脚本与回放入口 | 不向前端暴露原始 CDP 地址、模型密钥或无作用域控制接口 |

通路为：Chat → 持久浏览器任务 → TAP 创建浏览器 → browser-use 在线执行 → TAP 冻结动作与结果证据 → OpenCode 整理脚本 → TAP 保存不可变脚本包。用户之后选择回放，才由 TAP 启动独立 Playwright 执行。

browser-use runtime 属于 TAP AI 的受控模型工作负载，通过任务专属私有 CDP 通道连接 TAP 托管浏览器。该通道由 TAP 创建、撤销并关联项目、任务、浏览器和控制权代次；不得直接复用无授权裸 CDP 端口。浏览器代理与网络隔离仍由 TAP 强制执行，不能只依靠库的 `allowed_domains` 或提示词。

控制通道必须覆盖导航、标签、输入及脚本执行等能改变页面的路径；人工接管时撤销 Agent 写入能力并确认未决动作的结果，再授予用户控制权。仅在 step hook 中检查暂停不足以证明互斥。具体 CDP 转发与只读观察的覆盖范围必须在实施前做兼容验证；未覆盖的访问路径关闭，不能降级为不受控直连。

OpenCode 整理阶段延续现有隔离工作区和模型网关，输入为受限只读证据包，输出为冻结制品。网页内容与轨迹是数据，不能成为新的系统指令、工具授权或网络权限。新路径不把整个浏览器任务先启动为 OpenCode 编码任务；一般编码任务与原生知识任务的现有路由保持各自职责。

## 4. 会话控制、登录和人工接管

会话同时只有一个可写操作者：browser-use、用户或回放执行器。OpenCode 不在这一集合。控制请求带项目、会话、期望代次和幂等键；TAP 持久化控制回执，旧连接、旧代次和并发接管者不能继续写入。动作粒度记录请求、已派发、已完成或结果未知；传输重试不能假定外部站点具备幂等性。

| 当前情况 | 产品行为与执行约束 |
| --- | --- |
| 正在运行，用户要求接管 | 进入“正在暂停”，停止派发新动作；结算未决动作并撤销 Agent 写通道后，才进入人工控制 |
| 用户登录或处理验证码 | 在浏览器画面中直接输入；密码、验证码及完整登录表单不进入模型或脚本证据包；保留人工前置条件标记 |
| 用户交还控制 | 撤销人工写通道；递增代次；重新读取 URL、标签和页面状态，丢弃旧页面引用及未执行动作，再让 browser-use 决策 |
| 缺少业务资料 | 等待用户补充，保存有版本的输入增量；继续同一任务，保留累计费用和已发生动作 |
| 回放遇到登录、人工步骤或页面变化 | 暂停在当前步骤，保留已完成动作；交还后重新核对前置条件，不能从头自动提交一遍 |
| 浏览器或 worker 失联 | 核对存活进程、控制权和最后动作回执；结果不明记为未知并等待核对，不盲目派发旧动作 |
| 取消或硬期限到达 | 撤销所有操作者、停止模型及浏览器资源，收到停机证明后才显示已取消；已完成业务仍保留事实 |

人工接管期间停止模型观察；TAP 通过独立画面通道让用户看见浏览器。登录等敏感人工过程不录入默认动作截图和键入记录；用户交还后再采集页面观察，过滤凭据字段。普通人工业务动作可以记录，但必须标记 `actor=user`；无法可靠记录的操作保留为人工步骤，不伪造自动化代码。

等待输入和人工接管不持续消耗模型调用，但受冻结的会话空闲期限与绝对资源期限约束；界面显示剩余时间，到期关闭浏览器并保留证据。主动执行期限、等待期限与任务总预算分别记录，恢复不重置既有用量。

## 5. 动作轨迹、结果与证据

TAP 保存结构化动作事实，而非仅保存 browser-use 最终 JSON 或自然语言总结。轨迹包含成功动作、失败尝试、人工步骤和未知结果；OpenCode 整理的可回放路径可省去失败试探，但原始轨迹不可删改，成功业务动作的顺序与效果必须可追溯。

每个动作记录 `task_id`、`session_id`、`action_id`、递增序号、控制权代次、操作者、动作类型、标签/框架身份、前后页面观察引用、目标元素语义与定位依据、脱敏参数或秘密引用、开始/完成时间、结果及证据摘要。截图坐标或临时 DOM 索引不能单独作为稳定脚本定位依据。一次模型步骤可能包含多个动作，必须逐动作结算；不能把整个步骤的成功标志复制给每个动作。

结果记录分开表达模型判断和可核对事实。browser-use 报告 done/success 不直接变成产品完成：查询结果需要页面来源与提取证据，文件下载需要实际文件回执，提交动作需要确认页面或目的系统回执。无法核对时标记待核对或未知，不因模型总结积极而宣布成功；无回执的已派发提交不得自动重试。

截图、结构化结果、下载文件和轨迹由 TAP 非 AI 对象存储保存，执行记录保存类型、字节数、SHA-256 与项目作用域引用。模型原始思考不作为产品证据导出。OpenCode 只获得整理所需的脱敏页面片段、动作和证据，不复制账号状态、cookie、令牌或整个 browser-use 原始上下文。

实时画面与证据存储分离：用户查看经过授权的浏览器画面，刷新不会导致动作重放。多标签、新窗口、iframe、对话框、上传下载须关联同一个任务和授权范围；下载为任务制品，上传只取用户明确提供的任务文件。新站点或跨站登录超出获准来源时等待扩充授权；浏览器和人工控制都不能绕过现有网络策略。

## 6. 默认脚本产出

TAP 确认网页任务完成并冻结轨迹摘要后，自动且幂等地启动一次 OpenCode 整理。默认脚本生成预算在任务准入时与在线执行预算分别预留，总额仍受同一任务上限控制。预算不足或整理失败只影响脚本结果，不覆盖业务结果。

产物沿用 Playwright + TypeScript 和现有 bundle 存储；保留 `flow.spec.ts` 入口以复用执行器，用户界面统一称为“动作脚本”。测试运行器可以承载业务流程，但“测试通过”不再是实时业务任务唯一完成依据。

脚本包包含参数 schema、前置条件、人工步骤、必要等待与结果检查、来源动作 ID 映射和证据摘要。普通输入从运行时 JSON 读取，敏感值采用秘密引用或人工输入，不写成脚本常量。人工登录转换为“需要已登录/用户登录”的前置条件；无法稳定定位的视觉动作或未记录人工操作明确为需要接管的步骤，不编造定位器，也不声称可全自动回放。

允许合并无副作用的重复观察和等待，但不得删除成功的业务变更、改变提交次数，或把真实页面读取替换成预期结果常量。每个可执行业务步骤都应映射到来源动作；输入与输出的关联必须从证据证明，不能默认把所有输入硬编码为原任务值。

生成后先做静态验证：类型/语法、入口与依赖范围、输入和来源映射完整性、凭据检查、声明的站点范围。静态通过显示“脚本已生成，尚未验证回放”。只有用户发起且实际完成的回放才能建立对应环境和输入下的验证记录；静态检查不能证明脚本没有隐藏副作用，执行隔离与授权始终生效。

失败、取消或结果未知的任务保留轨迹和部分结果，不自动生成标记为完整可回放的成功脚本。脚本生成过程被取消时保留已确认的业务完成事实。

## 7. 回放、修复与完成语义

冻结回放默认不调用模型，使用原脚本、原输入摘要，在新执行中按顺序操作；登录前置条件可由用户在新浏览器完成。修改输入后创建新输入修订和新的回放运行，不能再声称沿用原输入摘要，也不能继承旧输入下的验证结论。

页面结构变化、前置条件失败或结果检查失败时停止推进；保留具体失败位置和已产生的外部变化。用户可接管处理，也可请求修复。请求修复时由 browser-use 在有控制权的会话中重新观察必要页面并补充证据，OpenCode 随后只据证据生成新版本；两者不能同时操纵同一浏览器，OpenCode 永远不拿该浏览器写权限。新版本不自动从头运行，后续执行必须先核对已提交动作和起始条件。

对外分别展示：业务结果（进行中、等待、已完成、失败、取消或未知）、脚本结果（未开始、整理中、已生成或失败）、回放记录（每次独立结果及验证条件）。这些是领域结果，不在本设计中强行复用旧 `passed` 字段表达全部含义。整体任务在脚本整理期间继续显示进度，同时已完成的业务结果立即可见。

重复的回放请求使用相同幂等键只能创建一个运行；用户主动再次回放使用新请求，并保留来源任务、脚本版本、输入修订和执行谱系。TAP 的幂等性不等于第三方网站的提交幂等性。

## 8. 对现有设计和接口的影响

| 现有部分 | 调整 |
| --- | --- |
| Chat 与 workflow 任务底座 | 增加实时浏览器执行及脚本整理阶段，仍由同一父任务管理；不增加并行外层 LLM 浏览器规划器 |
| `opencode_runtime.py` | 原编码/冻结执行模式保留兼容；新整理入口消费轨迹，不调用 `browser.execute` 验证成功业务，也不持有现场浏览器控制权 |
| `CodingResult` / `BrowserArtifactAdapter` | 区分实时业务回执、脚本整理回执和回放回执；新在线完成不能要求预先存在 bundle |
| `browser_automation` 会话与 HTTP 合同 | 增加控制权交接、观察流、人工控制和在线执行回执；以版本化合同适配，保留旧资源可读与旧 bundle 可回放 |
| `BrowserExecution` | 现有 bundle 必填合同继续描述旧脚本执行；新增独立在线执行合同关联轨迹，后关联脚本，避免虚构空 bundle |
| Browser worker 与隔离 | 保留任务独立容器、代理、资源限额、停机回执；增加受控 CDP 和画面/输入通道 |
| 前端运行详情 | 增加当前页面、接管与交还、补料、业务结果/脚本结果、查看过程和执行回放；不以测试报告代替业务结果 |

本设计调整 [2026-11-07 核心设计](2026-11-07-tapper-web-automation-core-design.md)的“先产出脚本、独立执行才完成”主路径及仅取消的首版边界；保留其隔离、预算、项目归属和不可变证据规则。旧门禁及历史真实验证只证明旧模式，不能转记为 browser-use 新路径通过。

范围归产品路线图的通用任务与 Web 自动化增量，不变更 V1 六项能力及其验收。完整测试计划、用例、发布和正式测试 Run 仍遵循原测试资产设计。跨任务登录档案、浏览器崩溃后自动恢复、任意新网站必定成功不在本轮承诺内。

## 9. 模型、预算与资源约束

browser-use 与 OpenCode 的主模型、提取、总结、回退及库内部重试都经 TAP 受控模型通路到 LiteLLM。任务记录 provider、版本、模型修订和各阶段实际调用；未知费用不写零。等待用户不能触发库的隐式总结或回退循环继续花费。browser-use 内建费用统计是辅助观测，不能代替执行端准入和硬期限。

依赖版本在实施验证时固定到锁文件和镜像摘要，运行期间不下载依赖或升级。browser-use runtime 无宿主浏览器目录、Docker socket 或无限制外网；浏览器无模型密钥，OpenCode 整理容器无目标站点连接。停止任务同时终止相关模型工作负载和控制租约，不能只停止 UI 推送。任何未被网关覆盖的模型路径都阻止启用该集成。

## 10. 验收与交付门禁

| 门禁 | 必须证明的结果 |
| --- | --- |
| browser-use 适配 | 固定版本通过 LiteLLM 完成真实页面观察与动作；主/辅助/重试调用全部可归属并受预算限制，CDP 可受控撤销 |
| 单一控制权 | 接管完成后 Agent 零新写入；交还后旧用户连接失效，Agent 基于新页面观察继续；未决提交被核对，不重复 |
| 通用业务 | 至少两个站点、三类流程，含查询提取、表单提交和多页操作；覆盖多标签及上传下载，新增任务无需修改产品代码 |
| 业务与脚本独立 | 自有站服务端提交计数证明首次任务只提交一次；脚本整理自动触发但不再次访问或提交；整理失败不覆盖业务成功 |
| 脚本来源与换参 | 脚本步骤映射真实动作、结果来自页面；至少一个非敏感参数替换后取得新输入对应结果，而非原输入常量 |
| 回放 | 用户从 UI 启动新执行；有新的结果与证据、原制品不变，正常回放零模型调用；页面变化停止并保留已发生动作 |
| 登录和人工步骤 | 在独立浏览器人工登录、接管后返回 Agent；秘密不进入脚本或模型证据，人工前置条件不被伪装成自动步骤 |
| 异常与隔离 | 取消确实停机，预算/期限耗尽停止，断线不重复派发；跨项目、旧代次、未授权站点与下载路径越界均被拒绝 |

先用隔离自有站和确定性模型验证状态、提交次数、轨迹和 UI；随后通过完整 Tapper 产品链路验证真实 browser-use 模型执行、OpenCode 脚本整理和独立回放。至少一个公共站任务在实现后独立选定，只做获准的无真实业务副作用流程；付费真实模型运行单独取得明确预算授权。不能把 Python 独立探针、旧 OpenCode 通过记录或模型自述当成新链路验收。

文档确认后进入实施计划：先锁定 browser-use 与模型/CDP/动作采集的适配证据，再按可验收切片落地在线执行、人工控制、脚本整理和回放。任一关键门禁不成立时明确报告缺口，不静默改回“先写测试脚本”来宣称满足本设计。

## 11. 官方资料与证据边界

以下资料于 2026-11-08 核对，用于确定适配方向；它们不证明 TAP 已经完成集成。

- [Browser Use 产品划分](https://docs.browser-use.com/cloud/which-product)：本设计使用自运行开源库，不采用托管 Agent API。
- [Remote Browser](https://docs.browser-use.com/open-source/customize/browser/remote)：支持连接既有 CDP 浏览器，TAP 仍需自行验证连接治理。
- [Lifecycle Hooks](https://docs.browser-use.com/open-source/customize/hooks)：文档明确列出 step start/end；不能把 step 回调当作完整逐动作回执或强制暂停证明。
- [Agent 参数](https://docs.browser-use.com/open-source/customize/agent/all-parameters)：视觉、提取模型、回退及失败处理需纳入统一预算。
- [Output Format](https://docs.browser-use.com/open-source/customize/agent/output-format)：历史与结构化输出可作为适配输入，done/success 属于 Agent 报告，外部业务结果需独立核对。
- [browser-use README](https://github.com/browser-use/browser-use#readme)：支持历史保存及换参回放，提取和最终总结仍可能调用模型；不据此承诺独立 Playwright 导出或零模型回放。
