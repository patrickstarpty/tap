## 1. 参考系统的职责划分

| 系统 | 主循环与上下文 | 扩展方式 | 对 Tapper 的启示 |
| --- | --- | --- | --- |
| Codex | 执行框架管理会话、上下文、模型与工具循环和持续执行 | app-server、业务上下文及 MCP 工具 | 复用执行框架，产品保留业务及操作边界 |
| Claude Code | 收集上下文、行动、验证并按反馈调整；保存会话并压缩上下文 | 内置工具、Skills、MCP、独立上下文子 Agent；Agent SDK 提供相同主循环和上下文管理 | 工具结果进入下一轮决策，计划可随证据调整 |

这些是官方资料支持的架构事实，不代表实现完全相同、恢复无条件可靠或相同模型表现相等。

## 2. 当前接入与缺口

- `tapper_runtime.py` 默认构造 `BrowserUseRuntime`；它与 TAP BDD 执行器控制现场浏览器，脚本调用确定性 `compile_replay`，没有运行 OpenCode 主 Agent。
- `browser_use_runtime.py` 在观察页面前生成并审查完整动作合约；操作种类、目标文本及顺序提前冻结，SDK 只定位当前步骤。

- 成功动作主要返回进度摘要，失败主要返回错误文本；失败计数提供止损，尚无统一的证据查询与恢复协议。
- browser-use 视觉、planning、judge 和显式 thinking 字段被关闭。`use_thinking=False` 不等于关闭模型服务端推理；不能简单全开这些选项来代替职责设计。

## 3. 方案选择

| 方案 | 取舍 |
| --- | --- |
| **OpenCode 主控，TAP 提供产品与工具集成（推荐）** | 符合用户目标，可复用会话、压缩、编码、工具循环和纠错；仍需验证模型与工具适配 |
| browser-use 主控 | 适合聚焦网页任务，不符合本轮对标通用 Agent 的主架构目标 |
| 切换 Codex、Claude Agent SDK 或 DeepSeek Harness | 可作基准及备选；本轮不同时替换模型、执行框架和产品接口，避免无法归因 |

推荐的数据流：用户目标进入 Tapper，Tapper 将任务上下文和工具交给 OpenCode；OpenCode 调用文件、终端、测试、浏览器及业务工具，真实回执返回原会话，主 Agent 据此继续。TAP 同时保存证据并检查业务验收条件。

**OpenCode 拥有主会话和通用决策循环。** 目标分解、工具选择、历史、上下文压缩、代码修改、测试与纠错优先复用现有能力。TAP 不在每次工具调用外再启动模型规定下一步。

**browser-use 提供浏览器能力。** 首先暴露观察、导航、定位、点击、输入、选择、条件等待和读值等类型化工具，供 OpenCode 直接调用；复用会话与页面感知。已安装版本是否有稳定适配接口，需要用最小纵向验证确认。

browser-use 完整 Agent 可作为未来可选的明确委派子任务，不能与 OpenCode 同时决定同一页面的下一步。首阶段不引入嵌套自主循环；以后采用时必须有子任务身份、独立预算、取消传播、结构化回执和页面单写归属。

**TAP 拥有产品事实与执行边界。** 项目/任务身份、用户输入、授权、预算、业务工具、隔离、证据、产物版本及验收仍归 TAP。Agent 声称成功不等于业务通过。

## 4. 应复用和必须补齐的接口

### 持续会话与上下文

一个 TAP 任务关联持久 OpenCode session ID。补充要求、失败反馈和恢复进入原会话，不每次重发长提示或只保留最近六条。

OpenCode 管理历史与压缩；TAP 提供只读业务合约、验收状态、证据索引和必要的当前事实，通过工作区文件或类型化工具按需获取。压缩后仍可获取原始输入与证据，摘要不是事实真值。

不另外实现通用消息压缩器、通用 Agent 调度器或推理循环。压缩、子任务及修复模型调用均进入现有费用账本；只有实测发现明确缺口，才补最小适配。

### 类型化工具与可靠反馈

浏览器能力直接注册为 OpenCode 工具或 MCP 工具，不再要求模型拼接 shell、转义 JSON 和辅助脚本。保留已验证的浏览器执行服务及安全检查。

统一回执包含动作 ID、观察版本、执行状态、实际值、前后页面状态、证据引用、耗时和错误类别。区分未派发、已完成、已知失败和结果未知；定位、页面阻塞、参数解析与环境错误分开。

写动作基于当前页面证据，由执行服务验证任务归属、目标和权限。终端及脚本执行同样受工作区、网络和授权边界约束，不能成为绕过浏览器检查或证据收集的旁路。

### 自主纠错与停止

将原始错误、实际值及相关页面/测试证据反馈给原 OpenCode 会话，由主 Agent 决定重新观察、改变合法定位方式、修改脚本或运行验证。保留正常工具循环，不另写通用“猜下一步”状态机。

TAP 控制预算、期限、权限和重复无进展。相同状态下不重复相同失败动作；获得新证据后才考虑有效重试。动作超时先查询回执并核对实际状态；未知副作用不能盲目重发。

环境监督器只自动恢复任务自有资源，共享 Docker 重启继续单独授权。模型调用前检查环境、浏览器/CDP 和模型目录，避免把环境异常交给模型反复推理。

### BDD、事实与验收

BDD 固定业务输入、结果条件和授权范围，作为进度及验收契约。定位器、页面交互方式和实现路径随真实观察调整，不在看页面前冻结所有机械动作。

步骤完成引用工具证据。事实保存原始值、语义值、来源和依赖；输入改变后旧结果失效。Agent 可以改变方法，不能修改产品、输入、预期结果或权限来得到通过。

真实业务通过和脚本回放分别验收。已支持操作继续确定性导出；需要 OpenCode 编辑或修复脚本时，记录模型调用和新脚本版本。冻结后的普通回放仍零模型调用，失败不能被自动付费修复掩盖。

## 5. 最小纵向验证与对照

先验证真实 OpenCode 主会话、qwen3.8-max、浏览器工具适配、TAP 账本和证据，不先重写整个任务平台。

1. 锁定版本验证：模型协议、工具 Schema、长输出、取消、会话继续和上下文压缩，保存实际版本及配置证据。
2. 本地完整任务：读页面、填写、读结果、保存产物；注入过期引用或异步更新，证明原会话根据反馈调整并完成。
3. 长任务与恢复：超过六步并触发压缩或中断，确认原要求、未完成项和关键证据仍可检索，不重复未知副作用。
4. 同一模型、任务、工具环境和预算，对照直接 OpenCode 与 Tapper 集成。直接运行成功而集成失败时优先定位集成损失；两者都失败时再分析工具、模型和任务。
5. 门禁通过后 FWD/AIA 各一次真实全链路：指定输入、实际非零报价、JSON、截图、trace、原录像、脚本及独立零模型回放。失败先保存复现证据，不做同配置盲重跑。

指标包括任务完成率、纠错成功率、重复无进展次数、上下文丢失、工具协议失败、费用和耗时。框架接通、测试数量、主 Agent 手工完成均不替代验收；不承诺接入 OpenCode 就自动达到 Codex/Claude Code 同等表现。

首阶段复用旧 OpenCode 会话/网关/隔离代码和现有浏览器执行器，改变默认主控关系和脆弱的工具传递方式。文件、终端、测试及业务工具通过同一主会话接入，各产品能力仍逐项验收。
