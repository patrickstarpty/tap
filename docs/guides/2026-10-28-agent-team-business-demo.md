## 1. 业务流程演示

演示角色：理赔团队负责人（演示身份 `tapper-local-user`）。目标：新建一个理赔答疑 Agent，让它服务一段时间，处理一条差评，把它交给同事，最后向管理层出一份周报。

### 1.1 新建 Agent 并设置岗位

在"智能体 → 配置"新建 `理赔指引助手`，描述与系统提示词限定它只依据理赔指引与理赔表格作答。

![新建 Agent](../assets/agent-team-demo-2026-10-28/01-config-new-agent.png)

保存后切到"团队"标签，新成员立即出现在花名册，状态为"闲置"（还没有运行），负责人默认是创建人。

![新成员加入花名册](../assets/agent-team-demo-2026-10-28/02-team-card-joined.png)

打开档案的"设置"页填写岗位"理赔流程答疑员"，保存后有明确的成功提示。

![设置岗位](../assets/agent-team-demo-2026-10-28/03-profile-settings-job-title.png)

### 1.2 用这个 Agent 对话并评价

新建对话，选择 3 个理赔来源（理赔指引、重疾理赔表、住院／意外理赔表）和 `理赔指引助手`，提问"提交重疾理赔申请需要准备哪些材料？理赔金通过什么方式支付？"。真实模型（qwen-plus）返回带引用的回答，对第一轮点"没帮助"并留空说明。

![第一轮回答并点差评](../assets/agent-team-demo-2026-10-28/04-chat-first-answer-not-helpful.png)

第二轮追问"住院／意外理赔申请表的两个部分应该按什么顺序填写？分别由谁填写？"。

![第二轮回答](../assets/agent-team-demo-2026-10-28/05-chat-second-answer.png)

### 1.3 团队页看到产出

回到"团队"：卡片显示周期内运行 2 次、服务人数 1、满意度"样本不足"（评分不足 10 条），最近运行时间来自运行数据。

![团队总览](../assets/agent-team-demo-2026-10-28/00-team-overview.png)

![新 Agent 卡片](../assets/agent-team-demo-2026-10-28/06-team-card-after-runs.png)

档案"工作量"页给出趋势、主指标与调用量：2 次运行、失败 0、中位耗时 17.7 秒、成本 US$0.0063、模型调用 8 次。

![工作量](../assets/agent-team-demo-2026-10-28/07-profile-workload.png)

## 2. 审查结论

三位审查员分别覆盖后端指标计算与 Langfuse 适配器、后端存储／接口／导出／同步标签、前端，另有一次真实页面走查。没有 Critical 问题；下表是已修复的 Important 问题，其余 Minor 问题见第 3 节。

| 层 | 问题 | 处理 |
| --- | --- | --- |
| 后端 | 上一周期按日期形状猜预设：近 7 天、近 30 天、自定义若从 1 号开始，会被当成本月或整月对比 | `GET agent-team/report` 新增 `preset` 参数，前端随周期选择器传入；缺省才按形状推断 |
| 后端 | "中位耗时"实际是按 `outcome:` 分组后按运行数加权的平均，拒答占比高时偏差约 2 倍 | 每个 Agent 单独发一次按 `agent:` 标签过滤、不分组的 p50 查询，并发执行 |
| 后端 | 汇报页本周期与上一周期各用一个 10 秒期限，Langfuse 挂起时最长 18 秒且状态不一致 | 两个周期共享一个期限并发加载 |
| 后端 | Langfuse 不可用时 `servedAvg` 返回 0 而不是空 | 返回 `null`，契约改为可空 |
| 后端 | CSV 导出未防公式注入（Agent 名称、岗位可由用户填写） | 以 `=`、`+`、`-`、`@`、制表符、回车开头的文本单元格加前导单引号 |
| 前端 | 运行数据不可用时档案工作量图、服务对象、我的 Agent、汇报趋势显示 0 或"无"而非"运行数据暂不可用" | 按 `runtimeStatus` 渲染不可用标记 |
| 前端 | 时长格式会出现"1 m 60 s""59 m 60 s" | 先取整到秒再拆分；单位改为中英文案 |
| 前端 | 保存岗位、转交负责人没有成功提示，设置页不显示当前负责人 | 加成功提示与当前负责人 |

## 3. 其余修复

后端：极端日期（如 `9999-12-31`）返回 500 改为 400 `period_invalid`；冷缓存时统计、近 30 天、趋势、最近运行改为并发加载，并对同一键的并发请求去重，期限耗尽导致的超时不再负缓存 30 秒；Tapper 默认有待处理反馈时即使近期无运行也进入花名册；Skill 升级分类不再依赖绑定顺序；`trend.csv` 的粒度与不可用标记合写在首行，并新增 `bucket_end`；履历游标拒绝类型错误的字段；迁移 0036 回滚时删除外键自动创建的索引；处理"不是待处理状态"的反馈不再写维护事件，处理说明去掉首尾空白，`tapper_default` 的处理时间改用注入时钟。

前端：默认视图不再重复请求花名册；"运行数据同步中"按运行状态标注，不再把正常的空值标成同步中；趋势读数与纵轴单位统一为"次"；卡片迷你趋势标明"近 30 天"；从"待我处理的反馈"打开档案直接落到"待处理反馈"页并显示反馈时间；导出 CSV 改为带加载与错误提示的请求；自定义周期在开始晚于结束时不再发请求；汇报页切换周期时显示刷新提示；筛选出错时保留筛选器；标签页支持方向键；小额成本不再显示为 US$0.00。

界面重做（保持信息架构）：顶部标签改为下划线式；指标区分成四个主指标与一行次指标；卡片改为员工名片式（头像、岗位、状态点、整宽迷你趋势、三格统计、脚注）；表格统一表头、数字右对齐、首列固定；组织架构图按负责人分组，仅在选中人员时画"使用"虚线；档案改为右侧滑出面板；汇报页改为纸张式版式，对比表用 ▲▼ 与柔色底，趋势图加网格线；加载用骨架屏；打印样式改为 A4 横向、不小于 9px、隐藏页头与控件。
