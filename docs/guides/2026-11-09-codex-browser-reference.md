## 可复用的业内做法

Playwright 推荐以面向用户的角色和标签定位元素，并通过严格匹配与可操作性检查处理可见性、稳定性和点击遮挡。弹窗盖住按钮时，应处理遮挡后再操作，不能依赖强制点击绕过问题。[Locators](https://playwright.dev/docs/locators)、[Auto-waiting](https://playwright.dev/docs/actionability)。

ARIA 快照提供页面的可访问结构，适合确定角色、名称和状态；截图能补充缺少语义标记的视觉状态。本次 AIA 性别/吸烟选项只有 generic 和图片，故补读对应 DOM 属性并核对截图。[ARIA snapshots](https://playwright.dev/docs/aria-snapshots)。

OpenAI 的公开 computer-use 资料描述的是重复观察、选择动作、执行并取得新状态的循环；工具整合资料强调工具应说明可观察与可修改的范围，实际执行方负责隔离、权限和真实结果回传。本次 Codex 工具同时暴露语义 DOM、只读 DOM 检查与截图，不能将它简单等同于纯截图 CUA，也不能由一次成功推断能完成任意网站任务。[Computer-Using Agent](https://openai.com/index/computer-using-agent/)、[Computer use integration recipes](https://developers.openai.com/api/docs/guides/tools-computer-use-integration)。

## Tapper 的具体差距与实现对应

| 层面 | Codex 本次实际做法 | Tapper 已有能力与当前缺口 | 应采用的通用行为 |
| --- | --- | --- | --- |
| 观察范围 | 长快照、目标 DOM 属性、可见弹窗、截图按需切换 | 已有 scoped snapshot 和完整回执文件；默认模型视图只有约 6000 字符，related_fields 约 2200 字符。长页面前缀与早期选项会挤掉当前弹窗的有效内容 | 优先暴露当前可见弹窗根及文本、关闭操作，再展示目标与背景；标明截断，并提供能继续读取的定位器 |
| 标签与内容 | Age 标签用于识别容器，列表文本用于识别选项 | collector 的 label 优先 aria-label，导致有标签的 popup 不包含选项文本 | 分开保留可访问名称与可见文本，不能把名称当内容 |
| 元素消歧 | 同名关闭按钮按可见性过滤；选项用 exact | select 已有精确可见选项和歧义拒绝；观察返回的 selector 仍需可靠定位真实可见对象 | 隐藏副本不得成为动作候选；可见目标仍多于一个时继续缩小范围，不选第一个碰运气 |
| 视觉反馈 | 截图直接作为图像返回，能核对 AIA 图标选中状态 | 当前原生工具路径把截图归档为 screenshot_ref，再以 JSON 字符串返回；未接通把该截图直接交给模型看的图像输入 | 保存截图与让模型看见截图是两件事；需要独立验证视觉输入链路与所选模型的能力，不能声称已有截图工具就已具备视觉纠错 |
| 只读控件 | 先读 readonly，再选择下拉/日历 | 工具已说明 fill 与 select 语义；控制状态必须在模型看到的观察内 | 只读是改变交互方法的信号，不是外部阻塞 |
| 时序与纠错 | 写入后读回；超时后先观察；加载中不提取旧报价 | 已有条件 read 与输入/结果验证分离；仍需要模型按回执采取纠错动作 | 已知失败、结果未知、加载中分开处理；未知写入先核实，不重放 |
| 工具往返 | 例如第 36 次调用合并日期、性别、吸烟和保额操作，然后统一回读 | tap_browser 每次只接受一个 action；每个低层操作都经过工具回执与下一轮模型决策 | 可审查是否支持有边界的确定性动作批次，但本次不改执行契约；减少往返不应跳过新页面观察或结果验证 |
| 结果真实性 | FWD 区分原价/优惠价；AIA 无金额即失败 | 已有 provenance 和 Then 验证；尚未证明真实站点任务都通过 | 必须验证准确输入和本次非零结果；导航、工具成功、结果页标题都不是业务成功 |
| 环境隔离 | 这次原生 Chrome 尝试干扰了用户窗口 | Tapper 任务专用浏览器是应保留的边界 | 浏览器故障不能成为接管个人窗口的理由；只在任务浏览器内恢复 |

代码依据：`deploy/browser/browser-tools.mjs` 的 modelReceipt 返回 JSON 字符串；`apps/backend/src/tap_platform/browser_automation/docker.py` 在归档时将 screenshot_data 替换为 screenshot_ref；本地运行继承该处理。此次弹窗补丁只完善文本观察，不宣称补齐视觉能力。

当前证据足以证明“观察投影丢失必要信息”是一个具体缺陷；不足以证明所有失败都由它引起，也不足以将剩余差距全部归因于模型。需要在同一任务、输入和预算下独立运行修复后的 Tapper，再区分观察、决策、工具执行和外部网站失败。

## 本轮补丁与已知边界

本轮补丁在目标位置做只读命中检查，返回拦截点击的元素；识别 dialog、alertdialog、aria-modal 和已有下拉/菜单，并优先反馈弹窗根和可见文本，不自动关闭或强制点击。复核发现的长文本静默截断和长定位器挤掉弹窗根两处边界均已修复：优先保留定位器、按剩余预算裁短文本并明确标记截断或遗漏。最终 50 项相关浏览器回归全部通过，独立复核通过；修复后的 qwen-plus 实跑仍失败。这说明观察改进是必要补丁，但还不足以解决模型决策问题。

尚有限制：父页面中没有任何弹窗语义的遮罩覆盖 iframe 时，iframe 内的命中检查看不到父页面遮罩。本轮没有扩大到跨框架命中链，因此不能声称能识别所有遮挡。

## 验证口径

1. 用受控长页面重现：带 aria-label 的尾部下拉、模态弹窗、关闭按钮隐藏副本、只读输入及原生日期选择器。
2. 先让回归测试暴露遗漏，再检查修复后模型实际收到的回执；不能只测试后台完整 DOM 文件里“其实存在”。
3. 每次修改只跑相关回归；浏览器层测试通过不等于真实模型验收通过。
4. 真实站点验收使用原始入口和合成输入，由 Tapper 自己操作、回读、提取和生成可回放产物。Codex 记录只作为对照，不给 Tapper 注入本次报价或固定网站答案。


## qwen-max 对照的新增诊断

同一入口和合成输入、单轮最多20次/$0.75，实际12次/$0.208871后主动取消。前5份计划都把 verification_kind=result 放在 keyword=And 上；工具只返回 invalid BDD plan step，模型重复计划及尚未获准的导航。后续模型自己缩减为单 Given 计划获接受，并启动导航；取消时无该导航的完成回执，因此不能断言整个流程未启动浏览器，也不能宣称完成任何页面验证。该轮不构成模型优劣结论。

证据保留在 `.superpowers/feedback-continuation/fwd-20261109-224838/`，包含13份原生工具调用、最终事件、用量账本和取消回执；只导出工具参数与结果，不导出模型私有推理。所有模型用量已结算，任务独立容器已清理。总账含历史保守预留为272次/$3.3187638；既有额度剩8次/$0.570909，不在本轮继续付费复跑。

OpenCode 输入窗口已接入现有 max_input_tokens，本次按网关30720配置；默认值129024不变，产品默认模型不变。5项定向测试及独立复核通过。

已据该真实错误补齐字段级反馈：JS 入口和 Python 计划处理器都会返回步骤索引/ID，说明 verification_kind 只允许用于 Then，并给出修正建议；非法值明确列出 input/result。保留原校验，不自动改写计划。实际 step_5/And/result 用例先失败后通过，JS browserctl 7项、Python BrowserProgress 21项回归通过。该补丁尚未付费实跑，不能声称模型必然能据此恢复。
