# ADR-030：知识切片采用保存、索引、启用直接生效

## 背景

用户要求将 Dify 的人工知识切片维护能力复制到 TAP，并明确确认操作与生效流程均按 Dify：保存触发索引，启用且索引完成即可检索，不强制独立复核、批准和发布。本决策调整 RFC-011 对知识使用的审批前置要求，不改变 Test Plan 自身评审与发布规则。

## 决策

- Library 以切片配置、预览、增改删、启停和批量维护为主要入口。原件与历史审阅记录保留。
- TAP AI 使用项目范围内当前就绪、存在启用切片的文档版本。知识问答、引用、Graph 增强、Insights 证据和测试生成统一遵守当前版本可用性；不伪造发布或批准记录。
- 切片更新生成不可变派生版本。索引完成前不得将旧内容当作更新后的有效知识；失败显示实际失败并支持重试。
- 原件下载验证上传原件的摘要；派生切片引用指向派生内容，不能冒充原件逐字摘录。
- 权限、项目隔离、并发版本校验和 Test Plan 发布条件继续有效。

## 考虑过的方案

保留强制审批前置不符合用户确认的 Dify 使用方式。自动批准会产生虚假的审批事实，因此不采用。

## 后果

历史审批数据继续可读；既有 published-sources 路径为兼容来源选择器返回当前可用资料，直接生效来源的 publicationId 和 expiresAt 为 null。历史严格发布适配器保留供既有记录核验，默认 Tapper 运行时采用本决策。

设计和实施证据见[能力对齐设计](../proposals/2026-09-27-dify-knowledge-chunk-parity.md)与[实施计划](../plans/2026-09-27-dify-knowledge-chunk-parity.md)。本决策获批不等于所有实现验收均完成。
