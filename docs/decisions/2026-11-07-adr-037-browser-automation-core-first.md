# ADR-037：通用 Web 自动化核心闭环优先交付

## 背景

用户明确 FWD 询价只是示例，目标是自然语言驱动不同网站的自动化；随后明确批准先交付核心闭环，复杂恢复和完整测试资产管理后补，保留权限隔离、费用上限和取消。

## 决策

按[核心设计](../superpowers/specs/2026-11-07-tapper-web-automation-core-design.md)先交付工作流浏览器任务。TAP AI 负责目标、OpenCode编码、模型预算和工作流投影；TAP非AI后端负责浏览器会话、冻结脚本包、执行回执和证据权威，通过项目作用域API协作，不跨应用import。首版使用内容寻址文件对象store及MySQL，后续对象适配可切MinIO。

首版明确为调试/浏览器任务执行，不称为已发布正式测试Run。保持ADR-024正式发布约束，完整测试资产迁移/发布以后实现，不建立第二个正式资产主写入口。运行只开放cancel，终态可重新执行冻结制品；复杂恢复、steer和节点retry不可用。

OpenCode使用network-none容器和监督器邮箱模型网关，保持单一编码Orchestrator。真实浏览器工具由TAP执行权威提供，生成与正式执行上下文隔离。旧八门禁状态与完整runtime ready保持真实；首版使用自身范围的独立实测验收。

## 考虑过的方案

先完成原四阶段全套能力会延迟可用核心；FWD专用脚本无法满足通用目标；将浏览器放进无隔离模型shell或让控制器代操作网页不能证明产品能力，因此均不采用。

## 后果

可以先验证核心产品价值，后续仍需完成复杂恢复和正式测试资产治理；当前不声称全站点无人介入或生产/LAN部署。现状架构仅在实现后更新为已交付。
