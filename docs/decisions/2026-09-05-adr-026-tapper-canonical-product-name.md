# ADR-026：Tapper 是智能工作区的规范名称

## 背景

TAP 平台的智能工作区需要统一的产品名称与视觉身份。当前验证环境仍把已退役名称嵌入界面、源代码、配置、持久化标识、文档和演示素材，继续保留会造成品牌、运行契约和客户材料不一致。

仓库已有 Tapper mark 与 wordmark。产品仍处于快速验证阶段，本地数据允许重建，因此没有必要为已退役命名承担生产级兼容迁移成本。

## 决策

- TAP 保持平台品牌；Tapper 是智能工作区、知识问答与 AI Agent 入口的规范名称。
- 最左上角显示完整 TAP 标识；一级 Tapper 入口使用方形 mark；展开的 Tapper 二级栏使用横向 wordmark。
- 当前工作树采用 clean cut：用户可见内容、活动代码符号、配置、进程、存储命名空间、文件路径、文档、图表与截图统一使用 Tapper，不提供旧名称兼容层。
- provider-neutral HTTP 路由、OpenAPI operation ID、`tap` package 与 `knowledge_*` 数据表不因品牌变化而更名。
- 旧本地数据不迁移也不自动删除；新版本在 Tapper 命名空间中重建验证状态。
- Git commit `0eab801` 是命名归一化前的字节级历史事实源；Git 历史不得重写。

## 考虑过的方案

- **仅替换界面和文档**：拒绝，因为活动配置、日志、脚本和文件路径仍会暴露冲突名称。
- **保留一轮兼容 alias 与数据迁移**：拒绝，因为当前没有生产租户或稳定外部调用方，复杂度不符合快速验证阶段。
- **全栈 clean cut**：采用，因为它提供单一规范名称、明确的品牌层级和可自动验证的零残留边界。

## 后果

- 本地使用者需要用新的环境变量和 Compose project 重新启动并重新摄取验证资料。
- 旧卷和存储对象仍存在，但普通命令不会读取或删除它们。
- 历史文档在当前工作树中的命名会被归一化；其原始字节由 commit `0eab801` 保留。
- 未来若进入生产数据迁移阶段，需要新的 RFC 和 ADR；本决策不授权对真实租户做破坏性重命名。
