# ADR-034：Tapper 回答执行与资产维护的应用模块归属

## 背景

Tapper 的回答阶段、冻结资源授权与期限控制分散在 HTTP service 和 worker 入口，非 HTTP 调用方也依赖该 service。Agent/Skill 修订写入直接调用团队视图和 Skill 库的数据库实现，使资产写入依赖报表模块。现有依赖检查约束了部分 import，却未表达这些业务职责的所有权。

## 决策

1. Knowledge 应用模块拥有会话回答的检索、生成、验证、保存及其冻结上下文授权。Chat 应用模块拥有回合图节点、工具循环和草稿批处理，通过 Knowledge 的明确公开接口调用知识能力。HTTP 仅负责传输转换；进程入口负责依赖组装、租约和进程生命周期。
2. 可恢复阶段是执行模块的内部接口。持久化 checkpoint 保留 schema v3，阶段编解码在持久化接缝处完成；执行上下文集中携带冻结输入、计划和授权函数。重试不能重置预算或绕过当前授权复检。
3. AI 模块拥有资产维护事件的值类型、表定义和同事务写入操作。Agent 团队视图和 Skill 库消费这些定义；资产修订与其维护事件仍由同一 SQLAlchemy session/transaction 原子提交。
4. 两个后端和两个前端保持现有隔离；不引入新网络调用、数据库迁移、依赖或通用插件框架。前端会话运行状态归 conversations feature，跨 feature 的来源与资产选择仍由 widget 组合。

## 考虑过的方案

- 仅拆分大文件：降低阅读单个文件的成本，但调用方仍须掌握阶段顺序、流式恢复和事务细节，不能解决本次问题。
- 通用编排框架或微服务：增加运行和测试接缝，当前没有相应替换需求。
- 异步维护事件：可以弱化直接依赖，但改变修订与维护记录的原子性，不符合本次行为兼容要求。

## 后果

对外产品行为、HTTP/SSE 和 checkpoint 数据保持兼容。内部 import 和测试入口会迁移，需通过接口行为测试及带负向样例的依赖检查约束。模块内部仍可有多个阶段和适配器；不以减少类数或文件行数判断完成。
