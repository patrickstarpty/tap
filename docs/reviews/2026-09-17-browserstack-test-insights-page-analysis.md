# BrowserStack Test Insights 逐页分析与 TAP 设计映射

研究日期：2026-09-17。仅阅读官方公开文档与TAP现有源码；没有登录或实测BrowserStack账户、SDK、API、连接器和套餐。下面的 TAP 落点均是目标设计，不是现有完成状态；交互、指标与技术架构见 [RFC-011 Insights 专题](../reference/2026-09-22-rfc-011-insights-contracts-design.md)。

## 对RFC-011的关键修订建议

1. **Test Insights内部区分两层。** 执行诊断回答“哪个批次/测试/数据行/尝试/步骤失败，什么证据，谁处理，何时复跑”；工程质量回答“覆盖、缺陷、自动化、交付效率、代码健康如何变化”。前者对应R&A，后者对应QEI。统一TAP入口可以保留二者层次，不把QEI当第二份测试报告。
2. **统一指标和身份先于AI解释。** 来源project/job/build/test/case IDs、稳定用例版本、平台矩阵、dataset row、attempt、CI rerun关联全部显式。名称用于显示/辅助映射，不是跨系统唯一键。同一Jenkins运行的JUnit/Allure重复上传只记一次；重试尝试不能去重消失。身份/错误签名/分类映射修改要带版本与生效范围。
3. **指标分母可见。** 首次通过率、最终通过率、重试恢复率、跨运行波动率不同；BrowserStack默认Flaky还包括近10次内retry转绿或pass/fail翻转>50%。TAP重试恢复率定义为“首次失败/执行错误且最后一次有效尝试通过的实例数 / 首次失败/执行错误实例数”，fail→pass→fail不算恢复。不能用一个recovered百分比宣称完整Flaky。未运行、跳过、取消、unknown、平台错误、缺报告、静音分别显示。静音是临时治理状态，保留负责人/理由/期限/恢复审计及含静音全量视图。
4. **覆盖分四种。** 测试库自动化比例/关键用例自动化比例来自用例库；需求覆盖来自版本化需求—用例关系；执行覆盖来自本次计划清单与事实；代码行/分支覆盖来自SonarQube等结果。不得把这些比例互换。缺陷密度分母是代码量还是需求数必须给单位；Cycle Time依赖状态历史和阶段映射。
5. **质量门禁与执行结果分列。** 规则作用于固定run_id、已完成数据水位、版本化profile和明确范围，输出通过/不通过/数据不足/计算中；无报告、超时、unknown不可默认为通过。不要用“最新构建”API绑定并发Jenkins门禁。用例数量阈值可以检查漏跑。后到数据或人工修正形成新判定版本，保留原判定。
6. **AI解释有证据和可修改流程。** 先稳定错误签名/规则匹配，再历史人工分类参考，最后AI生成候选原因、置信度和行动。R&A旧AFA要历史人工分类，regex优先于AFA；新Failure Analysis agent支持test RCA/build失败主题与受影响工作流。TAP显示“观察事实/推断/缺失证据”，补充资料只作用获授权分析任务；比较新旧结论，再采纳、关联缺陷、发起授权复跑。AI不能修改执行状态、重算未定义指标或自己通过质量门禁。

## 简明目标交互

- 默认质量总览保存项目/版本/平台/环境/时间筛选，所有卡片显示样本数、计算定义、数据截至时间和缺失来源；无来源是“未接入/同步失败/数据不足”，不显示0。
- 从异常指标下钻测试健康/错误组，再到批次—逻辑测试—数据行—attempt—步骤；切换平台与首次/重试/最终结果仍保留筛选。证据区按时间串联日志、截图、视频、请求与原报告，标注缺失/过期。
- “解释此失败/解释变化”读取当前筛选与已授权证据，返回引用及可继续调查的问题；人工可改分类、指派负责人、评论、关联缺陷、暂时静音或发起新Jenkins运行，保留审计。
- 工程质量页分Coverage、Quality、Automation、Velocity、Code Health；指标定义和来源映射可查看，跨团队比较使用一致定义。综合评分另公开权重/阈值/缺数处理，历史版本不混算。
- 接入管理显示凭证健康、选定项目、字段/阶段映射、初次导入进度、最后成功同步、水位/延迟、未映射数量、失败记录与补数动作。权限内分享/导出/订阅不得绕过数据范围。

## 技术与职责

`正式执行清单 → Jenkins/执行器 → 原报告/证据入对象存储 + MySQL接收记录 → 校验/身份映射/幂等/纠错事件 → ClickHouse明细与汇总 → TAP统一授权查询 → 看板/门禁/告警/TAP AI解释`。

- TAP独立前后端拥有执行与Insights。ClickHouse为必选、唯一平台指标事实与分析层；MySQL拥有连接/映射/接收/处理进度、规则版本、门禁判定、人工归因、问题状态与权限；对象存储拥有不可变原报告和证据及到期策略。记录事件时间/接收时间、来源版本/删除标记，支持迟到与定向重算，不把数据库最终合并当幂等保证。
- TAP AI独立前后端拥有知识、计划、用例和AI。通过授权查询服务取白名单指标/明细/证据，不直连分析数据库；每次工具调用重新限定项目/数据范围和预算，返回query_id、时间窗、分子分母、定义版本、水位及证据引用。复杂调查可用LangGraph，模型统一后端LiteLLM。
- Milvus只负责获授权文档/知识检索；不充当实时测试指标库。主 RFC 已选定 chDB，仅用于已审核文件表的临时受限计算，输入限任务授权快照、禁止任意路径/网络/写入并限制行数/内存/时长；不能成为第二平台指标事实库或让模型自由SQL绕过指标定义。
- Jenkins成功只代表job状态；只有真实测试报告可计算测试级指标。QEI Jenkins页当前只保证JUnit XML，TAP Allure需要单独适配与验收。首次优先TAP/Jenkins/JUnit/Allure，再分批接Jira、TestRail/Zephyr、SonarQube和其他CI。
- 外部连接器须验证分页、游标、限流、凭证轮换、源删除与历史补数；HTTP200不意味着数据完整。通知独立幂等事件/发送记录，不让重复报告重复发信。R&A应用日志仅按时间关联且未实现request tracing，并发测试可能都被匹配同一错误；TAP明确区分trace/request/attempt确定关联与时间重叠候选。
- PR/发布同时记录应用提交与测试代码提交，禁止缺少app SHA时退化为时间相近的最新同名build。按最新testhash状态生成的汇总报告不能代替固定发布清单；原始执行、手工修正和隔离治理视图都应注明口径。

## 文档限制、冲突与套餐

- QEI概览仍写Beta，条款仍写Trial、无服务/归档/SLA义务；其新功能页面并不能证明合同已变更。EU驻留与UDAC有Enterprise限定。
- QEI预置看板/指标入口仍描述四域，但独立Code Health页已提供八项SonarQube指标。NQS仍为四因子0–5权重25/40/25/10，详细归一化专有，不能宣称已有代码健康分数因子。
- QEI权限页允许普通用户在类别尚无连接时创建连接，SonarQube页要求admin；GitLab页称每类别仅一个CI工具，而CI汇总说明支持多个工具的各自路径。需真实账户验证，不扩写成任意多实例能力。
- R&A AFA与新agent是两套相关能力，前者有历史标签前提，后者需启用BrowserStack AI且有FUP。TRA每1000执行/月分析30失败；Automate/App Automate按每parallel每月1000失败。Pattern Analysis仅paid。
- 数据保留分类型：R&A Free测试历史/断言60天、Pro1年、Enterprise2年；视频均30天、debug logs均60天。QEI条款没有可照搬的明确固定保留天数。TAP应独立定义事实/原报告/视频/AI结果保留与删除联动。
- R&A更新profile方法标题PUT而curl示例POST；附件分页pageSize与page_size、type大小写；自愈presignedUrl与presigned_url存在示例/表格不一致。只能记为契约待验，不能照抄执行。
- SDK并非统一无侵入：Cypress会禁用其他reporter，WDIO凭据配置位置可改变执行地点，CodeceptJS非Playwright/WDIO helper仅观测，Espresso需要测试APK且不支持JUnit5，Playwright Node要求专用runner。SpecFlow/Jest版本门槛、新旧Espresso插件版本、名称清洗规则有页面差异，逐框架记录而不推定互通。
- Run Summary/Build Comparison报告忽略人工override，部分Tests Health/Build Insights说明采用人工结果；Stability实际为通过执行占比而非1-Flaky。最新报告与旧对比页对unknown/skipped归类表述不同，不能合成一个未经验证的统一公式。

## TAP当前差距

[分析模型](../../apps/web/src/legacy/testAnalyticsModel.ts)读取fixtures并生成固定14天build/attempt与Synthetic execution evidence；[分析页面](../../apps/web/src/legacy/TestAnalyticsWorkspace.tsx)在前端计算首次通过与重试恢复等数值。[模拟运行状态](../../apps/web/src/legacy/artifacts/state.ts)的createSimulatedRun及AutomationWorkspace明示模拟和无真实证据。当前可复用筛选/图表/下钻交互结构，不能把示例数据、页面存在或单元测试当成真实执行、ClickHouse摄入、来源连接、质量门禁、AI归因或企业权限完成证据。

252个正文URL均已核读并有能力/限制/TAP落点；按提取正文SHA-256精确去重为251份内容（R115与R123完全相同），另有近似重复的旧页面在表中说明。35个跳转不计正文，目标均落在本清单且已读。唯一失败 **R250 `/dashboards/custom-dashboards` 返回HTTP404**，是现有正文中的失效链接；同名功能的有效路径R083 `/features/custom-dashboards`已读，但不以它伪装失效URL可访问。最终同产品正文链接闭包无未登记URL。

逐页记录包含原始 URL、正文状态、能力与限制以及 TAP 对应设计；来源导航/站点图、跳转目标、正文缓存指纹和产品范围内链接闭包均已核验。正文提取按HTML void tags和无h1页面分别处理，避免误截断；SDK各框架单独缓存与核读，完全相同段落采用全文一致性比较，逐页记录版本/runner/配置/功能差异，不用目录标题代替正文。

产品树外Automate/App Automate各语言SDK、Support、全站产品、博客、平台通用IAM等仅记录关联，不递归整个站点；不做登录账户、SDK运行、API调用或套餐实测。首轮遭HTTP429后停止高并发，只逐个每5秒补抓，成功缓存不重复下载；最终无429遗留，保留初始错误与修复记录。以下所有TAP映射均为目标设计。
