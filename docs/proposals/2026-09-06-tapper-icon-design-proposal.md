## 1. 本次结论

**以 Listening 啄木鸟建立 Tapper 的主品牌形象，以 Aha 表达发现线索、问题或灵感的时刻。**

| 使用位置                   | 采用形象           | 具体形式                                                        |
| -------------------------- | ------------------ | --------------------------------------------------------------- |
| 主品牌 LOGO                | Listening          | Listening 头像与现有 Tapper wordmark 组合；紧凑空间使用独立头像 |
| 页面右下角等常驻悬浮入口   | Listening          | 浅色或深色圆形头像，建议从 56 px 显示尺寸开始                   |
| 有新的、可供用户查看的发现 | Aha                | 临时切换为同规格 Aha 圆形头像；用户查看后恢复 Listening         |
| 较大的品牌展示区域         | Listening 全身形象 | 用于介绍页、品牌说明等有足够空间的场景                          |

两种状态共同构成一条清楚的叙事：**“我在听” → “我发现了！” → 回到倾听。**

## 2. 为什么需要独立图标

Tapper 是 TAP 平台的 AI 助手。现有 wordmark 已获得认可，适合门户标题和完整品牌展示；在其他业务页面中，右下角悬浮按钮、侧栏等空间需要更紧凑的视觉入口，让用户能够随手唤起 Tapper。

这次设计为完整名称补充了一个可识别的角色：在品牌区域看到名字，在工作页面看到同一位助手。独立图标、字标组合和状态形象共同建立一致的身份。

跨页面入口及状态切换是本提案确定的设计目标，本文不代表相关产品功能已经实现。

## 3. 为什么选择啄木鸟

### 品牌故事：对细小的线索保持好奇

测试工作常常从一个很小的问题开始：这句话是否有另一种理解？换一种操作顺序会怎样？正常路径通过了，边界情况是否也成立？

好的测试者会注意这些细节，愿意继续追问、尝试与验证，从看似正常的表面发现值得深入的问题。这正是 Tapper 希望体现的工作态度。

本设计借用啄木鸟“探查、轻敲、发现”的形象，把这种态度变成一个有记忆点的伙伴。Tapper 的名称也可以与 “tap” 的轻敲含义形成设计联想：一次小小的探查，可能带来一次重要的发现。这是品牌隐喻，不是对产品自动发现缺陷能力的保证。

### 三个关键词如何落到形象上

| 关键词 | 形象中的表达                             | 希望建立的产品联想             |
| ------ | ---------------------------------------- | ------------------------------ |
| 聪明   | 单眼侧脸、专注的眼神、克制的表情         | 先理解问题，再给出有依据的回应 |
| 敏锐   | 有辨识度的喙与橙冠，Aha 的三道发现提示线 | 留意容易被忽略的差异和线索     |
| 好奇   | 微抬头、倾听与探查的姿态                 | 愿意追问、尝试和继续探索       |

亲近感贯穿这三个关键词：圆润的身体、柔和的白颊曲线和自然的姿态，让它像一位愿意与你一起工作的同事。

造型延续本次已选中的 Listening 侧脸方向：保持单眼、短颈和紧凑比例，避免正面双眼直视、过长的颈部或过于锋利的轮廓改变角色气质。以上是设计意图，尚未通过代表性用户研究验证。

### 向管理层讲的一句话

> Tapper 是一位对细节保持好奇的测试伙伴：先认真听懂问题，再沿着线索探索，在有所发现时及时告诉你。

## 4. 为什么 Listening 做主 LOGO

主 LOGO 需要表达一个长期稳定的性格。Listening 的表情从容、专注，有交流感，适合反复出现在页面入口、品牌标题和助手头像中。

它的“聪明”通过侧脸与眼神表达，“好奇”通过微抬头与倾听姿态表达；克制的情绪也给后续交互留出了变化空间。因此，用户平时看到它，可以逐渐建立“Tapper 在这里，随时可以开始交流”的认识。

Aha 的情绪更鲜明。微张的喙、橙色口腔和三道提示线共同表达突然有所发现，适合一个具体时刻。将它用在新的发现上，可以让表情变化具有信息价值；如果始终展示 Aha，这种变化就难以承担提醒作用。

| 比较维度     | Listening                   | Aha                        |
| ------------ | --------------------------- | -------------------------- |
| 主要含义     | 专注倾听、持续可用          | 有所发现、想与你分享       |
| 情绪强度     | 从容、稳定                  | 明快、突出                 |
| 品牌职责     | 主 LOGO、默认头像、常驻入口 | 发现状态、结果提示         |
| 与用户的关系 | “我在这里，你可以开始说”    | “这里有一个值得看看的发现” |

这项选择来自本次设计讨论与视觉判断，不是识别率或用户偏好测试的结论。

## 5. 悬浮入口与状态使用规则

### 状态分工

| 触发场景                                 | 展示形象       | 设计语义                     |
| ---------------------------------------- | -------------- | ---------------------------- |
| 默认待用，用户尚未打开助手               | Listening      | Tapper 随时可以开始交流      |
| 出现新的、可供用户查看的线索、建议或问题 | Aha            | 提醒用户查看本次发现         |
| 用户查看了本次发现                       | 恢复 Listening | 回到持续倾听、等待下一次交流 |

Aha 表示“有发现”，不直接等同于“缺陷已经确认”。是否为已验证缺陷、待核实线索或建议，应由打开后的具体内容说明。交互原型已实现“收起时有新回复 → Aha → 查看后恢复 Listening”；正式产品还需对接真实回复事件。

### 已接入的交互原型

Test Management 与 Low Code Automation 页面右下角提供 56 px 的 Listening 入口；Tapper 及其 Agent、Skills、Library 页面不重复显示。展开后支持当前页面信息、快捷提问、轻量对话，以及携带对话、草稿和页面上下文在 Tapper 中继续。收起不丢失当前草稿，Escape 收起后焦点回到入口；已完成对话沿用现有浏览器本地保存机制。

回复是基于页面数据的预设原型建议，已明确标注，不代表真实模型推理、已确认缺陷或真实自动化执行。新建自动化尚未保存的表单内容不包含在上下文中。

### 入口形态

| 浅色入口                                                                                                                     | 深色入口                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| ![Listening 浅色圆形入口](../../apps/web/assets/brand/tapper/listening/png/launcher/tapper-listening-launcher-light-128.png) | ![Listening 深色圆形入口](../../apps/web/assets/brand/tapper/listening/png/launcher/tapper-listening-launcher-dark-128.png) |
| 暖白圆底、彩色 Listening                                                                                                     | 墨色圆底、暖白身体与橙冠                                                                                                    |

- 悬浮入口建议显示在 48–64 px，以 56 px 作为初始值；实际落位、间距和遮挡情况需要放入业务页面确认。
- 直接使用已导出的圆形入口文件，保持喙、冠尖和 Aha 提示线的安全留白。
- 独立头像优先使用 48 px 及以上尺寸。24–32 px 可用于受限空间，但表情与细线信息会减少。
- 彩色和墨色头像适合浅色背景；深色背景使用反白版本或自带圆底的入口版本。
- 首次使用、悬停或键盘聚焦时，提供“打开 Tapper”等名称提示；发现状态可配“Tapper 有新发现”，让图形与明确的操作含义共同出现。

主 LOGO 与默认入口均保持 Listening。Aha 的切换发生在表达发现的场景中，门户品牌标题不随每次发现改变。

## 8. 本次希望管理层确认的事项

1. **品牌形象**：采用啄木鸟作为 Tapper 的助手形象，以“聪明、敏锐、好奇”为核心性格，并保持专业与亲近感。
2. **主标识与分工**：采用 Listening 头像与现有 wordmark 作为主 LOGO；Listening 常驻，Aha 用于有发现的时刻。
3. **应用原则**：延续现有品牌色与 wordmark，以当前素材进入真实业务页面验证，再确定入口落位和产品接入效果。

本次设计方向已形成，素材也已具备；管理层审阅重点是品牌采用与应用原则。

## 9. 汇报讲述建议

建议控制在约 8–10 分钟，按“为什么需要、为什么是它、如何使用、交付与确认”的顺序展开。

| 环节               | 建议时间 | 讲述重点                                               |
| ------------------ | -------- | ------------------------------------------------------ |
| 工作场景与品牌故事 | 2 分钟   | 测试者从细小线索出发，Tapper 在工作现场提供帮助        |
| 形象与性格         | 2 分钟   | 展示 Listening，解释聪明、敏锐、好奇与亲近感           |
| 主 LOGO 与双状态   | 2 分钟   | Listening 常驻，Aha 有发现；讲清两个表情的分工         |
| 素材与评审事项     | 2–4 分钟 | 展示两套素材，说明已完成的检查与待进行的页面、用户验证 |

### 可直接使用的开场

> 测试中的一个重要发现，常常始于一个很小的疑问：如果换一种顺序，如果这个条件不成立，会发生什么？
>
> 我们希望 Tapper 也带着这种聪明、敏锐和好奇陪伴用户工作。因此，我们选择了一只亲近的啄木鸟。它平时侧身倾听，让人愿意开始交流；有所发现时，它抬起精神，用一个 Aha 告诉你：这里值得看一看。
>
> 这就是这套形象的故事：“我在听”到“我发现了”。Listening 是主品牌与默认入口，Aha 是一次发现带来的回应。

### 常见追问

**为什么专业平台可以使用拟物角色？**

专业感可以通过克制的表情、简洁轮廓、一致配色和清晰用途建立。啄木鸟让抽象的助手有了可记忆的性格，也与测试工作中的探索和发现形成联系。是否被目标用户理解为专业、亲近，仍需要实际验证。

**为什么不用更醒目的 Aha 做主 LOGO？**

Listening 表达稳定的性格，适合长时间展示。Aha 的变化更适合一次具体发现，让用户在熟悉的角色上察觉到新的信息。

**为什么保留现有 wordmark？**

wordmark 已获得认可，承担完整名称识别；新增头像解决紧凑空间的入口识别。组合版直接复用现有字标，保持品牌连续性。

**素材完成是否代表可以直接发布？**

素材格式、基本视觉检查和交互原型接入已完成，原型已检查桌面、手机布局及键盘交互。正式产品能力接入、代表性用户验证与高层批准仍未完成。

### 建议结束语

> 我们希望 Tapper 成为一位愿意听、会探索、有发现就及时回应的伙伴。Listening 让它平时就在身边，Aha 让一次发现变得可见。
