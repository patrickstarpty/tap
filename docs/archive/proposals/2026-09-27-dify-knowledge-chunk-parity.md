# Dify 知识切片能力对齐设计

创建日期：2026-09-27。状态：用户已确认按 Dify 操作与生效流程实施。依据用户“一比一复制 Dify 的这个能力到 TAP”的要求编写；本文件是实现设计，不表示功能已经交付。

## 目标与基准

在 TAP 现有 Library 入口交付 Dify 式切片配置、预览与维护，覆盖 TAP AI 真实运行链路，并同步完整 `/prototype` 的交互。沿用 TAP 现有产品壳和视觉规范，不创建新的应用入口。

基准为本次查阅的 Dify 官方文档与公开源码：

- [切片配置与预览](https://docs.dify.ai/en/cloud/use-dify/knowledge/create-knowledge/chunking-and-cleaning-text)
- [文档与切片维护](https://docs.dify.ai/en/cloud/use-dify/knowledge/manage-knowledge/maintain-knowledge-documents)
- [切片列表、搜索、分页与批量操作](https://github.com/langgenius/dify/blob/main/web/app/components/datasets/documents/detail/completed/index.tsx)
- [文档详情、新增与批量导入](https://github.com/langgenius/dify/blob/main/web/app/components/datasets/documents/detail/index.tsx)

“对齐”要求用户操作和对应数据效果一致，不以按钮存在、固定样例响应或浏览器本地存储代替服务端能力。文件格式范围仍按 TAP 已支持的 PDF、DOCX、XLSX、MD、TXT；此需求不自动扩展为复制 Dify 全部应用编排、连接器和模型配置。

## 用户旅程

1. 从 Library 添加文档，选择文件后进入切片配置。
2. 选择通用或父子模式，设置清洗规则及切片参数，预览部分切片；明确预览数量与总量。调整参数后重新预览，尚未保存的配置不改变当前有效知识。
3. 保存并处理后查看实际索引进度、失败原因与重试入口。
4. 打开文档进入切片列表，按内容搜索、按全部/启用/禁用筛选，分页查看。每条展示序号、文本、长度、启用状态和已编辑标记。
5. 打开详情阅读完整切片并编辑；可新增、批量导入、单条/批量启停和删除。删除使用明确确认；失败保留输入与选中项。
6. 父子模式可展开子块，分别增删改；修改父块时选择重新生成子块或保留子块。子块修改不覆盖父块。Full Doc 模式的父块不可直接编辑，修改需更换原文档。
7. 索引完成后，用检索测试确认命中内容与上下文；已禁用和已删除切片不得进入新检索结果。

切片维护按索引模式提供关键词、摘要、图片附件操作；关键词仅在对应关键词索引模式可用，不在没有底层能力时显示可保存的空操作。Dify 的套餐限制不引入 TAP。

## 切片设置

- 通用模式：分隔符、最大字符长度、重叠字符数。
- 父子模式：父块按段落或整份文档组织；子块单独设置分隔符与最大长度。
- 清洗规则：合并连续空白；可选移除 URL 与电子邮件地址。预览和正式处理必须使用同一实现。
- 已建立知识集合的切片模式固定；文档级切片参数可更新。TAP 的 Source 是拟对应 Dify 知识集合的逻辑边界，Document 是其中的文档。
- 重新处理须提示会替换自动生成切片及其人工调整，保留可追溯的旧版本；不得静默覆盖已编辑内容。

## 数据与索引

原始文件仍按不可变版本保留。可编辑切片独立保存内容版本、父子关联、顺序、生成/人工来源、启用状态、已编辑状态、索引状态、操作者与更新时间。原文引用和人工编辑内容明确区分，避免把改写文字表示为原件逐字摘录。

切片命令通过项目权限、版本检查和持久任务驱动索引更新。保存成功与索引就绪分别呈现；模型或索引失败不能显示“已生效”。启停与删除同时约束查询侧当前可见性，防止异步清理期间返回旧内容。父子检索使用子块匹配并返回对应父块，返回前同时验证父块和子块当前状态。

批量命令报告成功和失败项；重试不得重复创建切片。搜索、计数、状态筛选和分页在服务端执行，不只过滤当前已加载页面。

## 与当前审核流程的关系

用户已确认 **Dify 一致流程**：保存触发索引更新，索引就绪且启用即可检索；不强制独立复核、批准与发布。当前审核记录保留为历史，不伪造审批人或自动通过审批来绕过门禁。

同步调整检索授权、来源选择器、引用核验及下游知识使用条件；项目访问控制仍有效。

## 迁移与交付

从已有不可变切片清单回填切片管理数据，保留文档、来源和原件版本关联。迁移可重入；旧引用按已有权限和历史策略读取，不重新指向修改后的文本。修改数据模型时使用仓库现有迁移体系，不在请求中临时创建表。

后端实现位于 `apps/tap-ai-backend` 知识模块，契约同步到 `contracts/`；运行界面位于 `apps/tap-ai-frontend`。`apps/web` 只同步完整产品原型，不改变 TAP 与 TAP AI 的运行边界。

## 验收

- 预览与正式处理在相同原件和参数下产生相同切片内容；参数变化能观察到边界变化。
- 刷新与服务重启后，切片内容、启停、已编辑标记、配置和父子关系保留。
- 修改后的内容能被真实检索命中；禁用、删除的内容不能被新检索命中。
- 编辑父块的两种子块处理方式分别测试；子块修改不影响父块内容。
- 并发旧版本保存被拒绝并保留用户草稿；索引失败可重试且不报告成功生效。
- 批量操作、跨页搜索、空结果、全部禁用、删除最后一个切片具有确定行为。
- 完整原型与运行界面分别做浏览器验证；按产品基准保留模块导航和跨模块旅程，保存前后截图。
- UI 样例测试、真实持久化测试和真实模型检索验证分别报告，不混淆验收证据。

## 本轮支持范围与明确限制

本轮对齐现有 TAP 文本文档与向量检索的切片流程。当前没有经济型关键词索引、图片附件或自动摘要处理，因此不提供对应空操作；不声称复制了 Dify 所有知识库模式。Full Doc 父块受现有索引上下文限制，最多 32,768 字符；超过限制显示错误而不会假装成功。完整原型沿用一个 Source 对应一份样例文件的结构，运行后端按真实 Source 集合锁定切片模式。
